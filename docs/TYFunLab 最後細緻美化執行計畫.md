# TYFunLab 最後細緻美化執行計畫

## 執行範圍

1. 只處理現有頁面的細節質感、掃讀性、日夜模式一致性與狀態色穩定性。
2. 不重排首頁資訊架構。
3. 不改歌曲資料、API、搜尋邏輯、收藏邏輯、投票邏輯。
4. 不導入新的 UI runtime 套件。
5. 不加入裝飾性漸層球、漂浮卡片、行銷 hero 或大面積單色濾鏡。

## 設計方向

1. 將 KTV 網站的活力控制在「夜間霓虹、日光暖亮、資料清楚」三個方向內。
2. 保持 `有收錄`、`MV`、`導唱` 三種狀態色分離。
3. 使用 cyan 表示收錄與資料確認。
4. 使用 pink 表示 MV 與主要 CTA。
5. 使用 amber 表示導唱、現場校對與注意訊息。
6. 保持背景有層次，但不要讓頁面變成暗沉、粉紅過量或殯葬業感。

## 第一階段：狀態色與表格掃讀收斂

1. 在 `src/index.css` 檔尾加入最終狀態色鎖定規則。
2. 強制 `status-availability` 使用 availability cyan。
3. 強制 `badge-official-mv` 與 `status-mv` 使用 MV pink。
4. 強制 `badge-guided-vocal` 與 `status-guided` 使用 guided amber。
5. 增加桌機表格列的細微交錯底色。
6. 保持表格 hover 不改變尺寸。
7. 保持 `-` 為低彩度文字，不加底色。

## 第二階段：日光模式彩度回補

1. 只調整日光模式的背景層次、hero 彩條、選取 chip 與提示區塊。
2. 讓日光模式比純白頁面更有溫度。
3. 保持表格主體偏乾淨，不使用大面積飽和色。
4. 保持文字對比清楚。

## 第三階段：手機首屏節奏整理

1. 穩定手機搜尋列內的 input、搜尋按鈕、篩選按鈕高度。
2. 防止搜尋按鈕與篩選按鈕壓縮文字。
3. 保持品牌列為橫向滑動，不讓它造成全頁橫向捲動。
4. 保持協作提示在手機上最多顯示兩行內文。

## 第四階段：驗證

1. 執行 `npm.cmd run build`。
2. 檢查 390px 手機寬度是否無全頁水平溢出。
3. 檢查日光模式首頁、暗色模式首頁、地區熱度頁、快速狀態頁、FAQ、遊戲頁。
4. 確認 `有收錄`、`MV`、`導唱` 三種標籤在日夜模式皆可分辨。
5. 確認沒有新增正式程式以外的暫存檔進入 commit。
