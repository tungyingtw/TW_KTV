## MV 與音訊語意風險

1. `brand.mvType` 目前 191,810 筆全部為 `official_mv`。
2. `brand.audioType` 目前 191,810 筆全部為 `original_vocal`。
3. 這兩個分布不像逐首逐品牌驗證後的自然結果。
4. 在確認資料來源前，不得把它們當作可信的現場功能資料。
5. 若確認只是匯入預設值，必須改成未標記，避免前台誤顯示大量「原版 MV」或「原聲原唱」。

## 欄位處理建議

### 第一批：`brand.note`

執行以下規則：

1. 刪除純匯入來源 note：`點碼對照更新`、`台灣點歌王 20260730 匯入`、`星○ KTV 歌單匯入`、`名冊反查寫入`。
2. 含「點歌碼衝突」的 note 不得直接刪除。
3. 產生候選檔並比對品牌狀態數不得變動。
4. 前台不得顯示任何差異。
5. 後台歌曲狀態編輯器仍必須可新增新的管理者 note。

### 第二批：`audioType` 與 `mvType`

執行以下規則：

1. 先確認匯入來源是否真的能證明 `official_mv` 或 `original_vocal`。
2. 若無法證明，將批次預設值改成未標記。
3. 保留後台採納、社群投票或人工編輯產生的明確值。
4. 前台必須把未標記呈現為未知，不得呈現為否定。

### 第三批：`available`

執行以下規則：

1. 先調整前後台讀取邏輯，讓品牌 key 存在即可代表收錄。
2. 保留後台可寫入 `available: false` 的能力，處理明確未收錄或覆寫資料。
3. 完成相容後才產生候選檔移除大量 `available: true`。

## 不建議刪除

1. 不得刪除 `code`，它是 KTV 點歌碼核心資料。
2. 不得刪除 `lyricsSnippet`，它被搜尋與詳情頁使用。
3. 不得刪除 `youtubeUrl`，它被詳情頁與參考連結使用。
4. 不得刪除 `zhuyin` 與 `pinyin`，它們被搜尋使用。
5. 不得刪除 `lyricist` 與 `composer`，它們被列表、卡片與詳情頁使用。
6. 不得刪除 `releaseYear`，它被排序與詳情頁使用。
