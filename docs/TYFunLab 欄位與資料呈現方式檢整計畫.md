# TYFunLab 欄位與資料呈現方式檢整計畫

## 目標

依照現有網站資料區塊逐項檢整，明確指定每個區塊的推薦呈現方式、可接受備案、不採用方式與理由。後續 AI 執行時必須依本文件的決策表處理，不得在實作時重新發想方向。

## 總原則

1. 先保留查詢效率，再增加設計感。
2. 資料狀態使用徽章、摘要、比較矩陣、資訊列或分組卡呈現。
3. 操作控制只在篩選、切換、送出、收藏、回報等互動位置使用。
4. 不將「收錄、MV、導唱」這類資料狀態改成 checkbox、switch 或表單控制。
5. 不將桌面多品牌比較矩陣改成純卡片牆。
6. 不新增大面積漸層、發光背景、裝飾卡片或單一粉色主題。

## 推薦呈現樣式定義

### Inline Summary

用於高層級摘要，例如歌曲數、品牌數、MV / 導唱對照。格式固定為「強數字 + 弱標籤 + 可選補充字」。所有項目共用 baseline，手機允許換行但不得變成卡片。

### Semantic Badge

用於短狀態，例如收錄、MV、導唱、語種。每種 badge 固定語意色：

| Badge | 色彩方向 | 用途 |
| --- | --- | --- |
| `status-availability` | 綠 / 青綠 | 有收錄、收錄數。 |
| `status-mv` | 藍 | 原版 MV、影音版本。 |
| `status-guided` | 青紫 / 紫青 | 導唱功能。 |
| `status-empty` | 灰 | 無資料、未收錄、尚未確認。 |
| `language-badge` | 低飽和多色 | 語種分類。 |

### Compare Matrix

用於桌面品牌對照。保留表格形式，透過表頭層級、列背景節奏、狀態徽章與空值弱化提升設計感。不得將矩陣改成卡片牆。

### Compact Status Table

用於手機結果列表。第一版固定使用四欄：「歌曲 / 收錄 / MV / 導唱」。若 390px 日夜截圖驗證失敗，才切換備案三欄：「歌曲 / 收錄 / 版本」，其中版本欄包含 `MV`、`導唱` 徽章。

### Collaboration Callout

用於「一起校對現場資訊」。樣式固定為協作資訊帶：

1. 左側 3px 色條。
2. 標題前有小狀態點。
3. 標題使用較高權重。
4. 內文行高固定，日夜模式使用同一段落寬度規則。
5. 關閉按鈕維持右上，不遮擋文字。

### Detail Data Group

用於歌曲詳情與社群投票。每個資料組必須有固定順序：標題、主要狀態、次要徽章、輔助說明、動作。不得讓投票、狀態與說明混成一段。

## 分階段執行指令

### 第一階段：完成本檢整文件

完成本文件並提交。不得修改 UI。

### 第二階段：狀態徽章與列表資料呈現

處理範圍：

1. `MatrixView`
2. `CardView`
3. `SongDetailModal`
4. 相關全域 CSS 狀態 class

執行內容：

1. 統一 `status-availability`、`status-mv`、`status-guided`、`status-empty`。
2. 修正「有收錄」與「導唱」共色問題。
3. 手機列表先維持四欄，不合併欄位。
4. 桌面矩陣只修徽章與掃描節奏，不重做版型。

驗證內容：

1. 390px 手機日光/夜間。
2. 1440px 桌面日光/夜間。
3. 搜尋結果、空值、至少一筆同時有收錄/MV/導唱的歌曲。

### 第三階段：協作資訊帶與社群校對資料模組

處理範圍：

1. 首頁「一起校對現場資訊」。
2. `BrandVoteBar`
3. `SongDetailModal` 內社群投票區。

執行內容：

1. 將首頁提示改成 Collaboration Callout。
2. 將社群投票三組資料固定分層：收錄對照、導唱功能、MV 類型。
3. 三組投票使用不同語意色。
4. 日夜模式內文斷行與高度維持接近。

### 第四階段：篩選控制表現微調

處理範圍：

1. `SearchBar`
2. `BottomSheetFilter`
3. `MobileSearchBar`

執行內容：

1. 將「原版 MV」與「有導唱」篩選改成 toggle chip / toggle row。
2. 保留語種、字數、品牌 chip。
3. 不使用系統 switch。
4. 不改搜尋與篩選邏輯。

### 第五階段：連入頁面與附屬頁一致性

處理範圍：

1. 靜態說明頁。
2. 地區熱度頁。
3. 小遊戲頁入口。
4. drawer、modal、表單附屬流程。

執行內容：

1. 清除舊樣板感。
2. 套用一致資訊層級。
3. 不將文章頁改成 landing page。
4. 不新增無實際資料意義的裝飾。

## 驗收標準

1. `npm.cmd run build` 必須通過。
2. 日光與夜間模式都必須能一眼區分收錄、MV、導唱。
3. 手機 390px 不得出現欄位文字擠壓或 badge 重疊。
4. 桌面矩陣必須維持品牌橫向比較能力。
5. 協作資訊帶必須比一般提醒醒目，但不得像錯誤警告或廣告。
6. 所有改動不得改資料結構、API 契約、搜尋邏輯、收藏邏輯、回報流程。

## 不處理項目

本計畫不重新設計整站資訊架構，不改品牌資料，不改歌曲資料來源，不改後端 API，不改搜尋演算法，不處理 SEO 文章內容重寫，不新增外部 UI 套件。
