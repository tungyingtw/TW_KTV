# TYFunLab 欄位與資料呈現方式檢整計畫

## 目標

檢整網站目前如何呈現歌曲、品牌、收錄狀態、MV、導唱、回報與統計資料，判斷哪些資料適合維持表格，哪些資料適合改成更有設計感的徽章、摘要條、分組卡、比較列或狀態圖示。執行時必須先判斷資料用途，不得只因為想美化就把清楚可用的表現方式硬改掉。

## 核心方向

1. 將「資料呈現」列為本階段主軸，將「控制項樣式」列為次要檢查項目。
2. 讓使用者更快看懂：哪首歌有收錄、哪些品牌有收錄、是否有 MV、是否有導唱、哪些資訊需要現場確認。
3. 維持 KTV 查詢工具的效率，不把所有內容改成大型卡片或裝飾排版。
4. 增加視覺設計感時，優先使用資訊層級、色彩語意、徽章組合、表格節奏與摘要模組，不使用浮誇漸層或過度發光。
5. 保留原本已經清楚、快速、符合使用情境的呈現方式；只修正辨識不清、層級混亂、色彩混用、行動版擁擠的區塊。

## 合適的資料呈現模式

### 1. 摘要列

用在「歌曲數、品牌數、MV / 導唱對照、結果數」這類高層級資訊。摘要列必須短、對齊、可快速掃描。不得把每個摘要都做成大型卡片，避免首頁變成儀表板或行銷頁。

執行時將 Hero 統計列維持一行或可換行的 inline summary。數字使用較高權重，標籤使用較低權重。日光與夜間模式都要讓三段基線對齊。

### 2. 狀態徽章

用在「有收錄、MV、導唱、未收錄、語種」這類短狀態。徽章必須有固定語意色，不得讓「有收錄」和「導唱」共用同一種主色。

執行時指定：

| 狀態 | 建議表現 | 語意 |
| --- | --- | --- |
| 有收錄 | 綠/青綠文字或小徽章 | 代表可在資料中找到收錄線索。 |
| 未收錄 | 淡灰文字或 dash | 代表目前沒有收錄線索，不要過度吸引注意。 |
| MV | 藍色小徽章 | 代表影音版本，不等於收錄本身。 |
| 導唱 | 青色或紫青小徽章 | 代表導唱功能，不與收錄共色。 |
| 語種 | 低飽和多色小徽章 | 協助分類，不搶過收錄狀態。 |

### 3. 比較矩陣

用在桌面多品牌對照。矩陣表格本身是合適的，因為使用者要橫向比較多家 KTV。不得為了「看起來比較設計」而移除表格。

執行時只改善：

1. 欄位寬度與表頭可讀性。
2. 品牌欄位的顏色提示。
3. 有收錄 / MV / 導唱的層級。
4. hover 與選中列的節奏。
5. 空狀態 dash 的弱化。

### 4. 壓縮列表

用在手機。手機不適合完整桌面矩陣，因此目前四欄壓縮表格可以保留。

執行時先保留「歌曲 / 收錄 / MV / 導唱」。只有在 390px 截圖中仍出現欄位擁擠或辨識困難時，才改成「歌曲 / 收錄 / 版本」，並在版本欄內用 `MV`、`導唱` 兩個徽章呈現。

### 5. 分組卡

用在歌曲詳情頁、社群投票、提供建議、回報流程。分組卡適合承載較完整的資訊，但不得把主列表改成滿版卡片牆，否則會降低查詢效率。

執行時將詳情頁資訊分成：

1. 歌曲身份：歌名、歌手、語種、年份、作詞作曲。
2. 現場狀態：各品牌收錄、MV、導唱。
3. 社群校對：收錄對照、導唱功能、MV 類型。
4. 使用者動作：收藏、回報、提供建議、預覽。

### 6. 特殊提示框

用在「一起校對現場資訊」。此區塊是網站信任感與社群參與的重要訊息，必須比一般提醒更有辨識度。

執行時讓它呈現為「協作提示」而不是「錯誤警告」。可使用左側色條、小圓點、短標題、較溫暖的底色與清楚的行高。日光與夜間模式文案斷行必須一致或至少視覺高度接近，避免同一段內容在兩個模式看起來像不同版型。

## 不建議的改法

1. 不要把「有收錄」改成 switch 或 checkbox，因為它是資料狀態，不是使用者控制。
2. 不要把桌面矩陣改成只有卡片，因為會破壞多品牌比較能力。
3. 不要把所有狀態都做成同一種高彩度膠囊，否則使用者無法分辨資訊主次。
4. 不要把語種、MV、導唱、收錄全部用品牌色表示，品牌色只服務品牌，不服務狀態語意。
5. 不要為了活潑而新增大面積粉色、紫色漸層或發光背景。
6. 不要把表單欄位全部 chip 化；資料輸入與回報仍需要清楚的表單控制。

## 控制項檢查補充

本階段仍需檢查控制項，但控制項不是主軸。

桌面搜尋區的「原版 MV」與「有導唱」目前是 checkbox，可評估改為 toggle chip，因為它們是篩選條件。手機 Bottom Sheet 可評估改為整列 toggle row。不要使用系統 switch，因為 switch 容易讓人誤會是永久設定。

「語種」、「字數」、「品牌」維持 chip 類型；「列表模式 / 小卡模式」維持 icon segmented control；「回報」、「提供建議」、「預覽」維持按鈕或連結按鈕。

## 分階段執行

### 第一階段：資料呈現盤點

完成本文件。不得修改 UI。讓使用者先確認目前判斷是否符合「透過不同顯示模式呈現資料」的期待。

### 第二階段：列表與狀態徽章試修

優先處理列表、小卡、詳情頁中「收錄 / MV / 導唱」的狀態呈現。統一語意色、徽章大小、空狀態與手機欄位層級。不得改資料邏輯。

### 第三階段：協作提示與社群校對區

處理「一起校對現場資訊」與歌曲詳情內的社群投票資訊。讓它們看起來像被設計過的資料模組，而不是一般提示文字。

### 第四階段：篩選控制視覺化

處理「原版 MV / 有導唱」篩選條件是否改成 toggle chip 或 toggle row。此階段只調整控制項外觀，不改搜尋邏輯。

### 第五階段：全站連入頁面一致性

檢查靜態說明頁、遊戲頁、地區熱度頁、詳情 modal、drawer、表單是否還有舊樣板感。只修正資料呈現與視覺層級，不重寫內容主題。

## 驗收標準

1. `npm.cmd run build` 必須通過。
2. 桌面 1440px 與手機 390px 都要檢查日光/夜間模式。
3. 使用者必須能一眼分辨「收錄、MV、導唱」三種資訊。
4. 搜尋結果列表必須維持查詢效率，不得因美化降低掃描速度。
5. 特殊提示框必須比一般資訊醒目，但不得像錯誤警告或廣告。
6. 任何改動不得改資料結構、API 契約、搜尋邏輯與收藏/回報流程。

## 下一步建議

先執行第二階段。原因是「收錄 / MV / 導唱」目前最常出現在首頁、手機列表、小卡、詳情頁，也最容易因色彩與徽章層級混用造成使用者誤解。先修這一層，比先改 checkbox/switch 更符合本計畫目標。
