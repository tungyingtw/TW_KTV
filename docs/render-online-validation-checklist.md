# Render 線上驗證清單

本文件用於線上版 push 後驗證。執行者必須依序檢查，不得只用本機 build 結果判斷上線成功。

## 1. 前台冷啟動

1. 開啟線上首頁。
2. 若 Render 正在冷啟動，必須確認畫面顯示載入或喚醒狀態。
3. 必須確認冷啟動期間不得直接誤顯示「目前沒有符合條件的歌曲」。
4. 等待資料載入完成後，必須確認歌曲列表正常出現。
5. 搜尋任一常見歌曲或歌手，必須確認結果會更新。

## 2. 前台歌曲列表與詳情

1. 用桌機寬度開啟首頁。
2. 必須確認列表欄位語意維持 `收錄`、`MV`、`導唱`，不得把其他音訊來源概念混進導唱欄。
3. 點擊任一歌曲列。
4. 必須確認列點擊動畫不得蓋在歌曲詳情彈窗上。
5. 用手機寬度重複第 2 到第 4 步。

## 3. 後台待處理

1. 登入後台。
2. 開啟「待處理」。
3. 選擇「全部」。
4. 必須確認已採納或已駁回項目不得顯示在待處理。
5. 選擇「收錄狀態待確認」並處理一筆資料。
6. 處理成功後，該項目必須從列表移除或列表必須刷新到不再包含該項目。
7. 重複檢查導唱功能與 MV 類型待確認。

## 4. 後台已採納與已駁回

1. 開啟「已採納」。
2. 必須確認剛採納的項目可查到。
3. 開啟「已駁回」。
4. 駁回一筆測試資料後，必須確認該項目可查到。
5. 點擊查看來源時，必須能理解原始回報或投票脈絡。

## 5. 系統維護資料成長摘要

1. 開啟「系統維護」。
2. 必須確認資料成長摘要載入成功。
3. 必須確認摘要包含 reports、votes、review actions、admin logs。
4. 必須確認 reports 與 review actions 顯示主檔上限與封存數。
5. 必須確認 votes 顯示 active entries 與 archived entries。

## 6. 封存資料查詢與下載

1. 在「系統維護」找到「封存資料查詢」。
2. 必須確認區塊顯示已處理回報、審核處理記錄、已處理投票訊號。
3. 若有封存檔，下載其中一份。
4. 必須確認下載內容是 JSON。
5. 若沒有封存檔，必須確認畫面顯示「尚無封存檔」，不得顯示錯誤。

## 7. 全站備份

1. 在「系統維護」確認備份匯出估算。
2. 必須確認估算包含封存回報、封存審核、封存投票數量。
3. 點擊「下載全站備份」。
4. 必須確認按鈕進入等待狀態，避免重複點擊。
5. 下載完成後，必須確認 JSON 包含 `exportVersion: "1.1"`。
6. 必須確認 JSON 包含 `data.archives`。

## 8. 匯入備份預覽

1. 使用剛下載的全站備份執行匯入預覽。
2. 必須確認預覽顯示主檔資料數量。
3. 必須確認預覽顯示「封存資料」總筆數。
4. 若只是驗證，看到預覽後必須取消，不得真的覆寫線上資料。

## 9. 驗證後回報格式

完成後必須回報：

1. 冷啟動狀態是否正常。
2. 前台列表與彈窗是否正常。
3. 後台待處理項目是否能處理後消失。
4. 封存查詢與下載是否正常。
5. 全站備份是否包含封存資料。
6. 匯入預覽是否顯示封存資料。
7. 發現的錯誤、重現步驟、截圖或線上錯誤訊息。

## 2026-08-07 最新線上驗證重點

請優先驗證以下項目：

1. 首頁首次載入不應長時間空白；冷啟動時不得誤顯示「目前沒有符合條件的歌曲」。
2. 首頁歌曲總數與品牌篩選應正常顯示。
3. 搜尋歌名、歌手、語種時結果應正常；不應再因樣板文或假作詞作曲干擾搜尋。
4. 歌曲卡片與歌曲詳情不應顯示假年份、假作詞、假作曲或樣板辨識提示。
5. YouTube 參考按鈕仍應可點擊，並以歌手與歌名動態搜尋。
6. 手機篩選不應再出現「最新發行」排序。
7. 後台歌曲編輯儲存後，不應自動寫入空欄位、`AUTO`、今年年份、`available:true` 或空 `brand.code`。
8. 後台採納/駁回/待處理列表仍應正常刷新。

若以上項目通過，資料瘦身線上驗證可視為完成。若失敗，先檢查靜態 catalog、Redis 覆寫與 API 回傳來源，不要先刪資料。
